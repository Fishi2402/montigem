# Introduction

This document specifies current rules for writing documentation. These rules
specify what must be done to get a well-formated documentation, but may be
changed if new features are implemented.

Keywords:

-   must - something has to be done to guarantee a proper result. If the result
    was not guaranteed, it must be reported. Example: "comments must use `/** ...
    */` format"
-   should - something should be done to keep formatting consistent. Example:
    "indentation should be 2 spaces"

## MontiGem visualization library

Visualization (GUI components) library documentation is generated by
`comment2doc` part of MontiGem tool. Read `comment2doc` README if you are
interested in the details of the tool.

The inputs of the tool include

-   *documented components*: `*.gui`, `*.cd` files of MontiGem visualization
    library (in `umlp-rte/frontend` directory of the project)
-   *example usages*: `*.gui`, `*.java` files of `vis-lib` example project (in
    `examples/vis-lib/frontend/src/main` directory of the project)
-   *example images*: `*.png`, `*.jpeg`, `*.gif` files in img folder of docs (in
    `docs/img/components` directory of the project)

For `comment2doc` to produce well-formated documentation, the inputs have to
follow rules:

-   *documented components* must only use comments in `/** ... */` format,
    except copyright. Example `*.gui` file:
    ```ts
    /* (c) https://github.com/MontiCore/monticore */
    package mc.fenix.input;

    import mc.fenix.input.GemDropdownInputTypes.Option;
    import mc.fenix.input.GemTextInputTypes.GemTextInputValidity;

    /**
      The component is a dropdown field with an optional label. It is used whenever a
      user input is required, in which the user selects one from multiple options
    */
    component GemAutocompleteInput(
      /** Can be set to ensure the list of options is specific to the input field. */
      String id,
      /** Text describing the input field. */
      String labelText = "",
      /** A list of options for the autocomplete suggestions */
      List<Option> options,
      /**
        The input field's value. If it is linked to a variable, the value of the
        variable will change when the user enters a new value.
      */
      ?String entry,
      /** Whether the input field is disabled. */
      boolean disabled = false,
      /** Width of the input field. */
      String width = "100%",
      /** Height of the input field. */
      String height = "100%",
      /** An object representing the validation status of the field. */
      GemTextInputValidity validity,
      /** Text displayed when the field is empty. */
      String placeholder = "",
      /** Callback that is executed when a key is released. */
      Event<Object> keyRelease,
      /** Callback that is executed when a key is pressed. */
      Event<Object> keyPress
    )
    ```
    Example `*.cd` file:
    ```java
    /* (c) https://github.com/MontiCore/monticore */
    package mc.fenix.input;

    /**
      Types used in a GemDropdownInput component.
    */
    classdiagram GemDropdownInputTypes {

      /**
        An object representing a dropdown option.
      */
      public class Option {
        /**
          Value behind the option in a dropdown. An option typically represents an
          object, e.g. person, via human-readable name. The value is an identifier
          that represents the object in the logic implementation.
        */
        String value;
        /** Human-readable name representing the option. */
        String display;
        +Option(String value);
        +Option(String value, String display);
      }

    }
    ```
    -   doesn't matter if the comment is multiline or not
    -   the text is in Markdown format. Keep in mind that the format must
        conform to the one used by MkDocs, e.g., lists have a 4-space indent,
        must be preceded by a new line
    -   a comment should precede a `component`, input property of a `component`,
        a `classdiagram`, a `class`, `interface`, `enum`, and their attributes.
-   *documented components* should be properly formatted
    -   2-space indent
    -   `=` surrounded by spaces in default values assignments
    -   empty line before and after import list
    -   etc. Take a look at the example.
-   An *example usage* must contain the name of a *documented component* in its
    name and must additionally contain `My` or `Example` or both. Such *example
    usage* describes the usage of corresponding *documented component*.
    -   The package of *example usage* doesn't matter, as long as it is in the
        example directory of `comment2doc`
-   *example usages* should be properly formatted, same formating rules as for
    *documented components*
-   An *example image* must match an *example usage*. Such *example image* shows
    the visual result of a corresponding *example usage*.
    -   The directory of *example image* doesn't matter, as long as it is in the
        images directory of `comment2doc`
